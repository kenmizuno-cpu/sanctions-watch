## 1. 今回採用する拡張

既存の人物・団体名の制裁監視に、暗号資産アドレスの収集・根拠管理・差分監視を追加する。最初はOFAC SDNに明示された暗号資産アドレスを対象とし、現在のAdvanced XML取得、対象者ID（FixedRef）、取得監査、差分、永続化の部品を再利用する。

アドレス情報は次の段階で広げる。

1. OFACの公式掲載アドレス。
2. 捜査・司法機関が公開した事件関連アドレス。
3. 民間調査・利用者投稿などのリスク情報。
4. 自社入出金との照合、送金経路の関連分析。

「公式資料に掲載されている事実」「関係性の推定」「社内での対応判断」を別々に記録する。OFAC掲載との一致を、そのまま日本での法的な凍結義務や口座自動凍結の命令にしない。適用制度・対象プログラム・社内規程に基づく判断は別工程とする。

## 4. 情報の分類と対応の分離

| 分類コード | 日本語表示 | 記録する事実 | 初期の用途 |
| --- | --- | --- | --- |
| `OFFICIAL_SANCTIONS` | 公式制裁掲載 | 公表機関・掲載リスト・対象者・プログラム・掲載版 | 正確な照合結果と根拠を提示し、社内判断へ渡す |
| `LAW_ENFORCEMENT_REPORTED` | 捜査・司法機関の公表 | 事件、資料、記述上の役割、当該機関の主張 | レビュー候補 |
| `THREAT_INTELLIGENCE` | 民間の調査情報 | 調査主体・分析方法・根拠・対象期間 | レビュー・監視の参考 |
| `COMMUNITY_REPORTED` | 利用者等の投稿 | 投稿、検証状態、反証、訂正 | 未確認情報として監視の参考 |
| `ONCHAIN_RELATIONSHIP` | 送金上の関係・管理者推定 | 取引・経路・推定方法・限界 | 分析材料。公式掲載と混ぜない |

捜査資料には、被害者、押収後の保管先、取引所の共用先なども登場し得るため、資料中のアドレスを一律「犯罪者のアドレス」と登録しない。役割判定不能は要確認にする。

`match_result`（照合結果）、`review_status`（確認状況）、`policy_decision`（社内対応判断）を分離する。数値の信頼度を使う場合は根拠・尺度・評価方法も保存する。公式掲載の確実性と、犯罪関与の確実性を同じスコアにしない。

## 5. Crypto-1の実装範囲

### 5.1 取得と抽出

- 既存の正常取得したOFAC SDN Advanced XML原本を使う。追加の監視周期・大容量ダウンロードを先に増やさない。
- 実原本と公式スキーマ・参照表を確認してから、暗号資産アドレスの識別項目を解決する。要素名や種別ID、対象者IDの対応を推測で固定しない。
- 同じ原本世代の対象者IDへひも付ける。名称別名の行数によってアドレス行を増殖させない。
- 従来XMLとの比較は同一世代と確認できる原本で行い、異なる取得時点の不一致は別に扱う。
- 非SDNは将来の別リストとして扱う。掲載内容や制限の性質を確認せずSDNの凍結対象へ混ぜない。

### 5.2 台帳と識別

「アドレスの識別」と「出典ごとの掲載関係」は別テーブルにする。同一アドレスに複数対象者・出典があっても根拠を失わない。

| 項目群 | 最低限保存する値 |
| --- | --- |
| アドレス | 原文、正規化値、公式の通貨記号、確定できたネットワーク、ネットワーク判定根拠、形式・チェックサムの検証結果 |
| 掲載関係 | 出典、分類、リスト名、対象者ID、原本内のレコード識別子、対象者名、プログラム |
| 原本証跡 | 取得URL、原本ファイル、SHA256、原本内位置、抽出器の版、取得実行ID |
| 日時 | 明示された公表日・発効日とその精度、初回確認、最終成功確認、消失検知 |
| 状態 | 現在の公式掲載状態、取り込み状態、掲載終了候補、レビュー状態、社内対応判断 |

確定ネットワークでは `(network, normalized_address)` を識別キーの基本にする。出典関係はリスト・対象者ID・アドレス識別を含めて別に保持する。

公式の通貨記号は必ず原文で保持する。通貨記号だけで実際の利用ネットワークを確定できない場合は未確定として残す。同じ形式のアドレスから、他のネットワークにも公式掲載があると自動で広げない。未確定データは出典の通貨記号と原文で管理し、確定ネットワークのキーへ混ぜない。

正規化は形式ごとに定義・検証する。全種類の小文字化、内部空白・記号の除去、OCR誤字の補正を共通処理にしない。原文を保存し、変換内容を追跡できるようにする。不正形式でも公式原文は証跡として残し、有効な照合索引への登録を止める。未知形式は削除や0件として処理しない。

### 5.3 差分・反映・掲載終了

- 初回収録は「初回収録」。抽出器追加によって初めて拾った既存掲載は「収録補完」。新規指定・新規アドレス掲載とは区別する。
- 差分はアドレス追加、対象者への関係追加、関係変更、掲載終了候補を分ける。
- `source_hash`の変更だけで全件を変更通知しない。意味のある項目と原本更新は分ける。
- 取得・構造検証に失敗した場合は、現在マスターと正常比較元を保持し、状態を異常にする。最終成功確認日時を進めない。
- 初回の抽出0件、件数の急減、未解決種別、対象者IDの不整合は、検証不能として反映を止める。件数閾値は実原本を確認して設定する。
- 原本からアドレスが消えた場合は掲載終了候補。即時削除・社内制限解除に接続しない。
- アドレスの掲載終了と対象者の指定解除を区別する。同じアドレスの他の掲載関係も確認する。
- 承認はイベントID・原本ハッシュ・差分内容へ固定し、別の版へ使い回さない。
- 正常取得原本、比較元、差分、台帳、投影ファイルを同じ世代として永続化する。既存トランザクションとconcurrency方針を再利用する。
- 初回本番収録は件数・出典・比較結果のレビューを通す。その後の正常検証済み追加を自動収録するかは設定で明示する。データ収録と口座制限は別処理。

状態表示は「検知 → 取得 → 検証 → 差分生成 → 確認 → 承認 → 反映」。初回収録、反映停止、掲載終了候補も識別する。「反映」はアドレス台帳への反映なのか社内システムへの取込なのかを表示する。

### 5.4 ダッシュボードと出力

OFAC取得状態とアドレス抽出状態を分ける。既存の人物名の件数・差分欄をアドレス件数で上書きしない。

表示：最終確認、最終成功取得、最終抽出、ユニークアドレス数、掲載関係数、ネットワーク未確定数、検証不能数、差分、掲載終了レビュー、原本リンク、出力世代、社内取込確認。

保存先案（実装時に既存規約に合わせる）：

- `data/crypto/address_master.csv`
- `data/crypto/source_relations.csv`
- `data/crypto/evidence.jsonl`
- `data/crypto/diff/latest.csv`
- `data/review/crypto_address_queue.csv`
- `data/dashboard/crypto_status.csv`
- `data/dashboard/crypto_changes.csv`

差分なしの実行でも確認・監査は記録し、追加作業のSheets行は増やさない。再実行で同じイベントを復活・重複させない。掲載終了等の未解消レビューは残す。Apps Scriptの現在の稼働版を確認し、同期確認前はSheets反映済みと主張しない。

公式更新から15分以内の検知、30分以内の差分生成を目標とする。定期実行間隔を達成実績と扱わず、遅延と失敗を測る。公式公表時刻が不明なら分単位の公表起点SLAは算出しない。

## 6. Crypto-1の受入条件

1. 実原本に掲載されたアドレス・通貨記号・対象者IDを再現可能に抽出し、すべての出力行を原本内位置まで追える。
2. 原本の抽出対象件数と出力・重複・隔離・未知種別の内訳を照合でき、欠落を説明できる。
3. 同じ原本の再実行で同じ内容になり、差分・レビュー候補が重複しない。
4. 初回収録・収録補完・新規掲載を分けて表示できる。
5. 通信失敗、304時の原本欠損、空抽出、構造変更、未知形式、急減で異常が表示され、正常比較元は保たれる。
6. 複数対象者・複数出典の同一アドレスを保持でき、掲載関係を一つ失っても他の根拠を消さない。
7. 大文字小文字の扱い、形式検証、異なるネットワーク、ネットワーク不明、1文字違いについて一致・不一致・要確認を固定テストできる。
8. 掲載終了候補、再掲載、原本版の変更、保存失敗時の復旧を検証できる。
9. 人物・団体名の出力、OFAC既存の掲載終了処理、財務省・外務省・経産省の状態に意図しない変更がない。
10. 既存テストと追加の意味あるテストが通り、実原本の収録監査を提示できる。固定の過去件数を現在の成功条件にしない。

## 7. 後続工程の設計上の要点

Crypto-2：最初に取得先と公開資料を調査し、アドレスが明示された原本だけを候補化する。事件番号、記述上の役割、公表機関の主張、訂正・撤回を保持する。資料中の単なる例示・被害先・保管先を犯罪者所有と推定しない。

Crypto-3：取得条件、利用許諾、更新頻度、費用を確認して情報源を選ぶ。転載が多い情報を独立した複数根拠と数えない。民間情報や投稿からの口座自動凍結をこの工程の機能にしない。

Crypto-4：自社データは承認された分析環境で扱い、公開リポジトリへ置かない。直接取引と「中継アドレス一つを挟んだ経路」を明示し、曖昧なhop表現だけに頼らない。方向、金額、日時、対象資産、少額の一方的送金、共用ウォレット、取引所、ブリッジなどの影響を説明する。同一管理者という推定から公式制裁掲載を新規生成しない。

トークン発行者による凍結・ブラックリスト状態を将来収集する場合も、公式制裁・犯罪認定とは別分類にし、解除履歴と理由不明を記録する。今回は実装範囲外。
